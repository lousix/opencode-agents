### 【opencode-agents】【H-01】Plugin tools lack session ownership verification — cross-session IDOR and data manipulation

| 属性 | 值 |
|------|----|
| 漏洞名称 | Plugin tools lack session ownership verification — cross-session IDOR and data manipulation |
| 严重程度 | High |
| CVSS | 8.1 |
| CWE | CWE-863 |
| 置信度 | 已验证 |
| 漏洞类型 | IDOR |
| 复核结论 | VERIFIED / CONDITIONAL_SOURCE / KEEP |
| 位置 | `.opencode/plugin/audit-db.js:248` |
| 发现Agent | audit-d2d3d9-control |

#### 一、漏洞描述

All 16 plugin tools in audit-db.js operate on a shared database (~/.opencode/audit.db) without any session ownership or authorization checks. Any caller can: (1) insert findings into any session, (2) update/modify findings across sessions, (3) prematurely complete any session, (4) reference findings from other sessions in attack chains, (5) generate reports for any session. This enables cross-session data manipulation and IDOR.

#### 二、漏洞根因

攻击者可控输入从 .opencode/plugin/audit-db.js:8 进入系统，经业务转换后到达 .opencode/plugin/audit-db.js:709。链路中未记录有效净化、参数化、白名单或权限拦截。 根因是外部输入在到达危险操作前缺少有效安全边界控制，导致 IDOR 可被触发。

#### 三、攻击者利用方法

In serve mode: 1. Connect to port 4096 (no auth per F1334) 2. Call audit_save_finding(session_id=victim_session, title="Fake Critical", severity="Critical") → inject false finding 3. Call audit_update_finding_after_verification(finding_id=victim_finding, severity="Info") → downgrade real finding 4. Call audit_complete_session(session_id=victim_session) → prematurely close victim session

Not directly exploitable as a standalone vulnerability. The shared DB enables other vulnerabilities: F1335 (IDOR — cross-session data access via plugin tools) and F1336 (no encryption — local file read). The architectural issue is that all projects' audit data is in one file with no tenant boundary.

## 攻击链分析

### Serve Mode Auth Bypass → Finding Manipulation → Report Corruption [Critical]

An attacker exploits the unauthenticated OpenCode serve mode (port 4096) to access all 16 audit tools. Without session ownership checks, the attacker can: (1) enumerate all sessions, (2) inject fake Critical findings to inflate audit severity, (3) downgrade real Critical findings to Info to hide vulnerabilities, (4) prematurely close running sessions, (5) generate misleading reports with arbitrary output paths. This chain combines authentication bypass (D2) with authorization failure (D3) and business logic flaws (D9) to achieve complete audit data manipulation.

**攻击路径**:

1. **[M-01]** OpenCode serve mode exposes all 16 audit tools on port 4096 without authentication → Unauthenticated serve mode enables tool access
2. **[H-01]** Plugin tools lack session ownership verification — cross-session IDOR and data manipulation → Cross-session IDOR enables data manipulation
3. **[I-01]** auditGenerateReport output_dir parameter allows arbitrary filesystem write (path traversal) → Path traversal enables arbitrary file write
4. **[L-01]** auditUpdateFindingAfterVerification allows unrestricted field updates including severity downgrade (Mass Assignment) → Mass Assignment enables severity downgrade

### Serve Mode Auth Bypass → API Key Exfiltration + Path Traversal [Critical]

When opencode serve mode is active on port 4096 with no authentication (F1334), an attacker can: (1) Invoke the agent to execute bash commands and exfiltrate 6 LLM API keys from environment variables (F1348), and (2) Call audit_generate_report with a malicious output_dir to write arbitrary content to privileged filesystem paths (F1340). The wildcard bash permission (F1342) amplifies both attacks.

**攻击路径**:

1. **[M-01]** OpenCode serve mode exposes all 16 audit tools on port 4096 without authentication → No auth on serve HTTP API enables remote agent invocation
2. **[L-02]** API Key Exfiltration via Serve Mode (No Auth + Bash Wildcard) → Agent bash wildcard allows env command to exfiltrate API keys
3. **[H-02]** Report Output Path Not Validated — Arbitrary Directory Write via output_dir Parameter → output_dir path traversal writes report to arbitrary filesystem location
