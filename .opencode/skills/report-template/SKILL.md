# 单漏洞产品报告模板

> 一个数据库 finding 对应一个独立 Agent、一个 durable run 和一份中文 Markdown；`index.md` 同时合并所有确认漏洞的完整正文。

## 输出边界

- 单漏洞文件：`audit-reports/findings/{vuln_id}-{组件名称}-{中文漏洞名称}.md`。编号保证唯一；组件名称最多保留 48 个字符，漏洞名称最多保留 72 个字符，并统一执行路径安全化。
- 单漏洞禁止 HTML。
- PoC 的源码、命令、输出、负向对照和清理步骤直接写入本报告，不创建独立 PoC 文件或目录。
- 不使用 Docker 构建或验证 PoC。
- 所有自然语言使用中文；路径、函数、代码、命令、协议、CWE/CVE 等技术标识可保留原文。
- 不包含整体统计、D1-D10 覆盖、候选账本、其他漏洞、通用方法论或审计过程流水账。
- 误报不生成本模板，只在索引保留中文排除原因。

## 必需章节

```markdown
# 【项目】【漏洞编号】中文漏洞标题

| 属性 | 内容 |
|------|------|
| 组件名称 | user-service / 认证中心 / 订单模块 |
| 风险等级 | 中文等级 |
| 漏洞类型 | 技术类型 |
| CWE | CWE-XXX |
| 置信度 | 中文结论 |
| 核验结论 | 已核验；真实外部输入；危险点已确认 |
| 可利用性 | 可实际利用/满足条件后可利用 |
| 主位置 | `path/to/file:line` |

## 一、风险与产品影响
说明用户、业务、数据和产品能力受到的实际影响，并列出受影响资产和范围。

## 二、事实与根因
说明真实 Source、传播、缺失或可绕过的控制、最终 Sink，以及攻击者条件和利用难度。

## 三、代码与证据链
展示 Source→Transform/Sanitizer→Sink 总览。每个节点的位置旁必须同时展示组件名称、相关函数限定名称和代码上下文行范围。Critical/High/Medium 的 Source 与 Sink 各至少展示 8 行非空真实代码，关键 Transform/Sanitizer 至少 5 行；不得只展示正则命中的单行。

## 四、攻击前置条件与利用场景
列出认证、权限、配置、网络、版本等前置条件；按顺序写攻击步骤和利用限制。

## 五、安全影响与受影响范围
分别说明机密性、完整性、可用性，以及组件、接口、角色、租户、版本和数据范围。

## 六、安全核验与 PoC
先标明验证类型（可执行 PoC / 静态复现 / 回归测试 / 仅手工验证 / 未复现）和执行状态，再依次给出：安全边界、前置准备、完整源码、构建命令、运行命令、预期结果、真实观察结果、负向对照、清理命令和执行限制。源码使用真实语言围栏，命令使用 `bash`，执行日志使用 `console`；禁止把注释、伪代码或文字调用说明放入 `text` 围栏冒充 PoC。

未实际执行时必须明确写“未执行”，只能展示预期结果，不得生成或推测实际输出。`EXECUTED/FAILED` 状态必须带真实捕获的输出。C/C++ 内存安全问题的可执行 PoC/回归测试必须启用 ASAN、UBSAN 或 Valgrind。

## 七、修复方案
先给临时缓解，再列 P0/P1/P2 修复任务。每项包含修改位置、动作、原因和验收要求。

## 八、验收标准与回归测试
验收标准必须可判定；回归测试覆盖正向、反向、边界和权限场景。

## 九、关联位置与证据边界
列出相同根因的关联位置、关联漏洞和当前结论的代码/配置/环境边界。
```

## 产品质量门槛

| 标准 | 要求 |
|------|------|
| 可定位 | 主位置和每个证据节点有精确文件、行号、相关函数名和上下文行范围 |
| 可理解 | 不要求读者掌握审计框架术语即可理解产品影响 |
| 可复现 | 提供可复制的完整源码或可执行命令、负向对照、预期/实际结果和清理步骤 |
| 可修复 | 修复任务指向具体模块/函数/配置并说明实现动作 |
| 可验收 | 每项关键修复有明确验收条件和回归测试 |
| 有边界 | 不把未读取代码、未确认配置或特定环境假设写成事实 |

## 修复任务格式

建议使用结构化 JSON 落库：

```json
[
  {
    "priority": "P0",
    "target": "src/example/AuthService.java:validate",
    "action": "在进入危险操作前按资源所有者执行服务端授权校验，拒绝仅依赖客户端传入的用户编号。",
    "rationale": "从根因上阻止低权限用户访问其他用户资源。",
    "acceptance": "跨用户请求固定返回拒绝结果，同一用户合法请求保持原行为。"
  }
]
```

不接受“加强校验”“注意安全”“升级到最新版”这类无法实施和验收的描述。

## 汇总与合并详报

`index.md` 必须展示：

- 中文风险统计
- 每个确认漏洞的中文名称、等级、核验状态和 Markdown 链接
- 误报记录及中文排除原因
- D1-D10 执行状态和候选覆盖概览
- 按风险等级排列的全部确认漏洞完整正文，包括代码证据、PoC、修复方案和回归测试

`index.md` 的漏洞正文直接读取当前版本单漏洞 Markdown，禁止二次自由改写导致证据漂移。`index.html` 保持轻量索引，只提供统计和链接。
